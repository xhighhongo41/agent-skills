# plugin-update-check: プラグイン更新の有無を調べる

> **skill version**: 1.0.1

セッション内で初めて本スキルを使用するときは「plugin-update-check スキル v1.0.1 を使用します」と宣言する。

npm プラグインは、OpenCode 本体の機構では自動で最新版に追随しない。本スキルは設定に書かれたプラグインについて、導入済みの版とレジストリの最新版を突き合わせ、更新の要否を一覧にするための手順書である。

本スキルは判定だけを行い、**適用はしない**。適用（キャッシュの削除と入れ直し）は `plugin-update-apply` の役目である。分けてあるのは、調べるだけの操作と、一時的にプラグインを使えなくする操作を混ぜないためである。

## 前提

- 設定ファイルは `~/.config/opencode/opencode.json` または `~/.config/opencode/opencode.jsonc`。どちらもありうるので、存在する方を読む。`XDG_CONFIG_HOME` で移動されていれば、移動先を見る。
- プラグインのキャッシュは `~/.cache/opencode/packages/` にある。`XDG_CACHE_HOME` で移動されていれば、移動先にある。
- レジストリは `https://registry.npmjs.org/<パッケージ名>` で参照できる。

Windows では `~` をユーザープロファイル（`%USERPROFILE%`）に読み替える。

上の `XDG_CONFIG_HOME`・`XDG_CACHE_HOME` による移動と `~` の読み替えは、既定の場所で書いてある手順のコマンドのパスにも当てる。

## 手順

### 1. 設定からプラグインの一覧を取り出す

設定ファイルの `plugin` 配列を読む。版の指定（`@x.y.z`）が付いていても、**落とさず、そのまま記録する**。版の指定が付いたプラグインは、新しい版が出ていても意図して固定している可能性がある。以下ではこれを「版を固定しているプラグイン」と呼ぶ。

設定ファイルはコメントや末尾カンマを含むことがある。厳格な JSON パーサで読めなくても異常ではない。

### 2. レジストリの最新版を取得する

レジストリの API から直接取得する。この方法なら、node や npm が入っていない環境でも動く。

```bash
curl -sL "https://registry.npmjs.org/<パッケージ名>" | grep -o '"latest":"[^"]*"' | head -n1
```

スコープ付きパッケージは、**`/` を `%2f` に置き換える**。`@<スコープ>/<名前>` なら `@<スコープ>%2f<名前>` と書く。スコープの無いパッケージはそのままでよい。

### 3. 導入済みの版を確認する

キャッシュの中の `package.json` を読む。

```bash
cat ~/.cache/opencode/packages/<パッケージ名>/node_modules/<パッケージ名>/package.json | grep '"version"'
```

その `version` の値が導入済みの版である。

参照先を間違えないこと。**実際に入っているものは `node_modules` の下にある**。キャッシュの直下にも `package.json` があるが、そちらは `{"dependencies": {...}}` の形で要求した版を書いたものであって、実体ではない。

スコープ付きパッケージは、ディレクトリが `~/.cache/opencode/packages/@<スコープ>/<名前>/` の階層になる。また、`<パッケージ名>@latest` というディレクトリが併存することがある。

### 4. 比較して報告する

表にまとめる。

| プラグイン | 導入済み | 最新 | 状態 |
|---|---|---|---|
| （名前） | 1.0.0 | 1.0.0 | 最新 |
| （名前） | 1.2.0 | 1.3.0 | **更新あり** |

キャッシュかレジストリに見つからなかったものは、**エラーにせず、そのまま報告する**。設定に書いたばかりでまだ導入されていない場合や、パッケージ名が変わった場合がある。

版を固定しているプラグインは、最新版と違っていても**更新対象として扱わない**。固定を外すかどうかは利用者の判断であり、そのことを添えて知らせる。

「更新あり」が1件でもあれば、**再起動しただけでは更新されないことを併せて伝える**。npm プラグインは一度導入されるとキャッシュが固定されるため、キャッシュを消してからでないと新しい版が入らない。適用の手順は `plugin-update-apply` にある。
