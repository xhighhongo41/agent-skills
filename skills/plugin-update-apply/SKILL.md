# plugin-update-apply: プラグイン更新を適用する

> **skill version**: 1.0.0

セッション内で初めて本スキルを使用するときは「plugin-update-apply スキル v1.0.0 を使用します」と宣言する。

npm プラグインは一度導入されるとキャッシュが固定され、**再起動しただけでは新しい版に入れ替わらない**。
本スキルは**キャッシュを削除し、再起動によって最新版を入れ直す**ための手順書である。

更新の要否を調べるのは `plugin-update-check` の役目であり、**本スキルは適用だけを担う。**

## 承認の徹底（最優先の制約）

- キャッシュの削除自体は取り返しのつく操作だが、**再起動するまでそのプラグインが使えなくなる**ことがある。
- したがって、**削除を実行する前に、対象のプラグイン名と削除する理由を示し、明示的な承認を得る。**
  **承認が無いうちはファイルシステムに一切手を加えてはならない。**
- **曖昧な返事を承認とみなさない。** 「うーん」「まあ」のような返答は保留として扱い、もう一度確認する。
  実行してよいと読み取れる返答があったときにだけ次へ進む。

## 手順

### 1. 対象を特定する

`plugin-update-check` の結果、または新たに確認した更新対象を挙げる。

**版の指定（`@x.y.z`）で固定されているプラグインは対象にしない。** 固定を外すかどうかは
利用者の判断であり、勝手に最新へ動かしてよいものではない。

### 2. 承認を求める

**何がどうなるのかが分かる形で示してから尋ねる。** プラグイン名・現在の版・新しい版・
消すディレクトリを並べる。

消す対象は、パッケージごとに2つある。

```
~/.cache/opencode/packages/<パッケージ名>
~/.cache/opencode/packages/<パッケージ名>@latest
```

スコープ付きパッケージはディレクトリが階層になるので、パスは
`~/.cache/opencode/packages/@<スコープ>/<名前>` の形になる。**消す前にパスの実在を確かめる。**

### 3. 削除する

承認が得られたら実行する。**承認は手順2で1度得れば足りる**が、
**1件消すごとに結果を確かめてから次へ進む**（まとめて流して最後に確認しない）。

```bash
rm -rf ~/.cache/opencode/packages/<パッケージ名>
rm -rf ~/.cache/opencode/packages/<パッケージ名>@latest
```

**承認された対象の外へ広げない。** ワイルドカードでまとめて消すことはしない。

### 4. 削除できたことを確認する

```bash
ls ~/.cache/opencode/packages/<パッケージ名>/node_modules/<パッケージ名>/package.json 2>/dev/null
```

**何も出力されなければ削除できている。** `2>/dev/null` を付けるのは、
消えていること自体が期待どおりの結果であり、そのときのエラー出力に意味が無いためである。

### 5. 再起動を依頼する

キャッシュが消えたので、**次回の起動時に最新版が導入される。再起動は利用者が行う。**
都合のよいタイミングで再起動してもらうよう伝える。

### 6. 再起動後に確認する（任意）

再起動が済んだら、入った版を確かめる。

```bash
cat ~/.cache/opencode/packages/<パッケージ名>/node_modules/<パッケージ名>/package.json | grep '"version"'
```

`version` が期待した版になっていれば適用できている。
**参照するのは `node_modules` の下**である（キャッシュ直下の `package.json` は要求した版であって実体ではない）。

## うまくいかないときの確認

- **再起動しても版が変わらない**: **消し残りが無いかを確認する。** 手順2に挙げた2つの
  ディレクトリのうち、片方だけが消えている場合がある。
- **プラグインが読み込まれなくなった**: 設定に書かれた名前が正しいか、
  レジストリからそのパッケージが引けるかを確認する。ネットワークに繋がらない状態で
  再起動すると、消したまま入れ直せないことがある。
- **途中で失敗した**: どこまで消したかを必ず報告する。中途半端に消えた状態を隠さない。
