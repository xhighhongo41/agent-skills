# 外部由来スキルと参照物の照合・適用

skill-sync の手順3〜5から読む補助ファイルである。次の2つについて、照合と適用の手順を定める。

- **外部由来スキル**: 他者のリポジトリから register-external-skill で取り込んだスキル。
- **参照物**: スキルが宣言し、導入時に外部のリポジトリから取得してスキルのフォルダ内に置く資料。独立したスキルとしては導入しない。

「構成物」「配置の記録」は `contents.md`、「監査」は `audit.md` の定義に従う。状態の語（最新・更新あり・内容が違う など）と手順の番号は、`SKILL.md` のものである。

## 取得の手段

外部由来スキルも参照物も、一時ディレクトリへの浅いクローンで取得する。

```
git clone --depth 1 [--branch <ref>] <取得元> <一時ディレクトリ>
```

- 一時ディレクトリは作業中のリポジトリの外に置き、終了時に削除する。配置ではないので、「書き込みの範囲」の対象外である。
- 取得元と ref の組が同じなら、取得は1回でよい。ローカルのパスも同じコマンドで扱う。
- 取得後に `git rev-parse HEAD` でコミットを控える。
- 取得に失敗しても、別の取得手段へ勝手に切り替えない。
- 上流の先端だけを確かめたいときは、クローンせずに `git ls-remote <取得元> <ref>`（ref が無ければ `HEAD`）でコミットを問い合わせる。ref がタグのときは `refs/tags/<タグ>^{}` の行があればそれを見る（注釈付きタグをそのまま問い合わせると、タグ自身の識別子が返る）。

## 外部由来スキルの照合

`origin` を持つ行が対象である（「由来」列は「外部」）。配布元の `index.json` に接続できなくても、導入元ごとに行う。判定は上から順に当てる。

1. 取得できない、または取得できたが `origin-path` に `SKILL.md` が無い → 状態を付けず、備考に「未照合」（後者は「上流に無い」）と書く。更新の要否を判定できないので、手順4の候補にも入れない。
2. 上流の `metadata.version` があり、手元の版と違う → 更新あり。
3. 本文と付属ファイルを、記録・手元・上流の3者で比べ、下の表で決める。

**クローンを省ける場合。** 先に上流の先端のコミットを確かめる。それが `origin-commit` と同じで、付属ファイルの記録が有って古くなければ、上流は記録のときから変わっていない。クローンせずに、上流を「記録どおり」として、手元と記録だけを比べる。

**本文の比べ方。** 要約値を3つ比べる: 記録 S（`origin-digest`）、手元 L（手元の本文から計算）、上流 U（上流の本文から計算）。
本文は閉じ `---` の次の行以降（frontmatter が無ければ全文）、改行を LF に揃え、末尾の改行を1つにした UTF-8 の SHA-256（16進は小文字）で、`sha256:` を前に付けて表す。
register-external-skill の「要約値の計算」と同じ規則であり、直すときは両方を同時に直す。
frontmatter は比べない。手元の frontmatter は取り込み時に補われていることがあり、含めると常に「違う」になる。

**付属ファイルの比べ方。** `SKILL.md` を除く構成物を、記録（`.skill-sync/origin.sha256`）・手元・上流で比べる。

- 手元が記録と違う: 記録にあるファイルの内容が手元で違う、または手元に無い。
- 上流が記録と違う: 記録にあるファイルの内容が上流で違う、上流に無い、または記録に無いファイルが上流にある。
- 記録に無い手元のファイルは数えない。「手元にだけあるファイル」として備考で知らせる。

**判定。** 本文と付属ファイルの結果を合わせる。どちらか一方でも違えば「違う」とする。

| 手元 | 上流 | 状態 | 備考 |
|---|---|---|---|
| 記録どおり | 記録どおり | 最新 | — |
| 記録どおり | 違う | 更新あり | 「本文差分」「付属ファイル差分」のうち当たるものと、変わったファイル名 |
| 違う | 記録どおり | 内容が違う | 「ローカル改変」と、変わったファイル名。更新しない |
| 違う | 違う | 内容が違う | 「競合」と、差分の規模。更新しない |

**記録が無い場合・古い場合。**

- `origin-digest` が無い行は、本文の L と U だけを比べる。同じなら本文は「記録どおり」、違えば「内容が違う」（備考「記録なし」）とする。
- 付属ファイルの記録が無い行（記録を作らない版の skill-sync や register-external-skill が置いたもの）と、記録が古い行は、クローンを省かず、付属ファイルの手元と上流を直接比べる。同じなら、本文の判定をそのまま使い、備考に「付属ファイルの記録なし」を添える。違えば「内容が違う」（備考「記録なし」）とする。
- どちらの場合も、その行を選んで更新を1度適用すれば記録が作られる、と案内する（内容が同じなら、変わるのは記録だけである）。

「配布元に無い」は、外部由来の行には付けない（導入元がある）。

## 外部由来スキルへの適用

手順5の流れ（取得 → 監査 → 承認 → 配置 → 記録 → 検証）の中で、外部由来の行については次を行う。

1. **取得**: 導入元から、`origin-path` のディレクトリの構成物をすべて取得する（照合のときに取得済みなら、それを使う）。すべて取得できてから先へ進む。
2. **監査**: `audit.md` に従う。対象は、上流の構成物のうち、手元に無いファイルと、手元と内容が違うファイルである。`SKILL.md` は、本文の要約値が手元と違うときに対象とする。
3. **承認**: 手順5の承認に含める。
4. **配置**:
   - 手元の `SKILL.md` の frontmatter から、取り込み時に補われたキー（`name` / `description` と `metadata` の全キー）を控える。
   - 本文を上流の本文に置き換える。frontmatter は、上流に frontmatter があればそれを基に、無ければ手元のものを基にして、`metadata` の `origin` 系キーを重ねる。`name` は手元のもの（ディレクトリ名）を保つ。`description` は上流にあれば上流を採り、無ければ手元の補いを残す。
   - `SKILL.md` 以外の構成物は、取得したバイト列のまま置く。
   - 上流に無いファイルが手元に残っていれば、手順5の「手元にだけあるファイル」として扱う（消さない）。
5. **記録**: `origin-commit`（取得した HEAD）・`origin-digest`（上流本文の要約値）・`origin-fetched`（当日の日付。`YYYY-MM-DD`）を更新する。`origin` / `origin-path` / `origin-ref` は変えない。付属ファイルの記録（`.skill-sync/origin.sha256` と、`records.json` の `origin.commit`）を作り直す。
6. **検証**: 照合をやり直し、「最新」になることを確かめる。

外部由来スキルが宣言ファイルを持つ場合、その上流に `external/` があっても取得しない（参照物は宣言から取得する）。取得しなかった旨を報告する。

## 宣言ファイル

参照物を使うスキルは、フォルダ直下の `external.json`（宣言ファイル）に取得元を書いている。厳格な JSON である。

```json
{
  "format": 1,
  "externals": [
    {
      "name": "<参照物の名前>",
      "origin": "https://<ホスト>/<所有者>/<リポジトリ>",
      "path": "skills/<名前>",
      "include": ["SKILL.md", "references/"]
    }
  ]
}
```

| キー | 必須 | 値 |
|---|---|---|
| `format` | ○ | 常に `1` |
| `externals` | ○ | 参照物の配列（1件以上） |
| `externals[].name` | ○ | 参照物の名前。小文字英数字とハイフン。配列の中で重複しない。置き場 `external/<名前>/` のディレクトリ名になる |
| `externals[].origin` | ○ | 取得元の URL。ローカルのパスも受け付ける（外部由来スキルの導入元と同じ） |
| `externals[].path` | ○ | リポジトリ内のディレクトリの相対パス（ルート直下なら `.`） |
| `externals[].ref` | — | 取得するブランチかタグ。無ければ既定ブランチの先端 |
| `externals[].include` | — | `path` の下から取るものの配列。末尾が `/` ならディレクトリごと、そうでなければ1ファイル。無ければ `path` の下すべて |

未知のキーは無視する。

**宣言は、読むたびに形式を確かめる。** 宣言は他者が書いたものでありうる。次のどれかに当たる宣言は、宣言として扱わない。備考に「宣言ファイルの形式が違う」と理由を書き、その行の参照物は照合も取得もしない。

- JSON として読めない。`format` が `1` でない。`externals` が1件以上の配列でない。
- 要素に `name`・`origin`・`path` のどれかが無い、または文字列でない。
- `name` に小文字英数字とハイフン以外が含まれる、または重複している。
- `path` か `include` の要素が、空、絶対パス、`..` を含む、バックスラッシュを含む、のどれかに当たる（参照物の置き場の外を指しうる）。
- `origin` に認証情報（`<利用者名>@` の形）が含まれる。

**どの宣言を読むか。** 導入済みで本体を更新しない行は、手元の宣言を読む。未導入の行と、本体を更新する行は、これから置く宣言を読む（収録スキルは、配布元の `files` に `external.json` があれば取得する。外部由来スキルは、上流のものを読む）。

## 配置形

配置形とは、上流から取得したものを、手元に置く形に整えたものである。一時ディレクトリの中で作る。

1. 宣言の `path` の下から、`include` に従って取る。構成物の表（`contents.md`）で除くものは取らない。`include` に挙がっているのに上流に無いものがあれば、備考で知らせる（残りで配置形を作る）。
2. **ライセンスと帰属のファイルは、`include` に無くても必ず取る。** 対象は、`path` の直下とリポジトリの直下にある、名前に `LICENSE`・`LICENCE`・`NOTICE`・`COPYING` を含むファイルである（大文字小文字を区別しない）。配置形の直下に置く。同じ名前が両方にあれば、`path` の側を採る。
3. **`SKILL.md` という名前のファイルは、`SKILL.upstream.md` に改名する**（大文字小文字を区別しない。階層は変えない）。スキルのフォルダの下にある `SKILL.md` も独立したスキルとして読み込むエージェントがあり、そのまま置くと、参照物が別のスキルとして登録されてしまう。
4. シンボリックリンクは取らない。取らなかったリンクを報告する。
5. 配置形の一覧と要約値を作る（`contents.md` の形式。基準は配置形の最上位）。

## 参照物の照合

宣言ファイルを持つ行のうち、「対象外」でなく、自エージェントの置き場にある行が対象である。書き込めない場所にある行は、下の「書き込めない場所にある複製」で扱う。
参照物ごとに、次の表を上から順に当てる。

| # | 状況 | 見分け方 | 判定 | 備考に書くこと |
|---|---|---|---|---|
| 1 | 未取得 | `external/<名前>/` か、その記録（`.skill-sync/external/<名前>.sha256` と `records.json` の項目）が無い、または読めない | 未取得 | 「参照物 `<名前>` が未取得」 |
| 2 | 手元で変更 | 手元の `external/<名前>/` が記録の一覧と違う（内容が違う、無くなった） | 手元で変更 | 「参照物 `<名前>` のローカル改変」と、変わったファイル名 |
| 3 | 宣言が変わった | 宣言の `origin`・`path`・`ref`・`include` が、記録の写しと違う | 更新 | 「参照物 `<名前>` の宣言が変わった」 |
| 4 | 接続できない | 先端の問い合わせかクローンに失敗した | 未照合 | 「参照物 `<名前>` は未照合」 |
| 5 | 上流に更新 | 上流の先端が記録のコミットと違い、配置形の一覧が記録の一覧と違う | 更新 | 「参照物 `<名前>` に更新」と、変わったファイル名 |
| 6 | 変わりなし | 上流の先端が記録のコミットと同じ。または、違うが配置形の一覧が記録と同じ | 最新 | — |

- **照合のために接続してよいのは、配置の記録にある取得元だけである。** 1（未取得）と 3（宣言が変わった）は、接続せずに判定する。利用者がまだ見ていない接続先へ、対象が選ばれる前に取りに行かない。
- 5 と 6 を見分けるにはクローンが要る。上流が進んでいても、取るファイルに違いが無ければ更新にしない。判定の段階では記録を書き換えない。
- 記録に無いファイルが `external/<名前>/` に残っている場合と、宣言に無い名前のディレクトリが `external/` に残っている場合は、判定を変えずに備考で知らせる（「参照物 `<名前>` に手元にだけあるファイル N 件」「宣言から外れた参照物 `<名前>` が残っている」）。消さない。

### 行の状態へのまとめ方

本体の判定（版・内容。外部由来スキルは上の「外部由来スキルの照合」）を先に決め、参照物の判定を次のように重ねる。

- 「対象外」は、他のすべてに優先する。対象外の行では、参照物を照合しない。
- **本体が「最新」のときだけ、参照物の判定が行の状態になる。** 「手元で変更」の参照物が1つでもあれば「内容が違う」、そうでなく「未取得」か「更新」の参照物が1つでもあれば「更新あり」、どちらも無ければ「最新」である。「未照合」は行の状態を変えない。
- 本体が「最新」以外のときは、行の状態は本体の判定のままにし、参照物の状況を備考に並べる。
- 宣言ファイルを持つ行は、対象を選ぶ一覧に、参照物の名前と取得元を示す。

### 選ぶ単位と既定の候補

- 選ぶ単位は、本体と、参照物ごとに分ける。本体の更新と、参照物の取得・更新は、別々に選べる。
- 既定で候補に入る参照物は、「未取得」と「更新」である。未導入のスキルを導入するときは、その参照物も既定で候補に入る。
- 「手元で変更」の参照物は、既定で候補から外す。外すのはその参照物だけで、本体や他の参照物の更新は止めない。含めるかは個別に確認し、上書きすると手元の変更が消えることを伝える。

## 参照物への適用

手順5の流れの中で、選ばれた参照物については次を行う。収録スキルや外部由来スキルの本体も同じ適用で更新するときは、新しい宣言に従う。

1. **取得**: 宣言の取得元から取得し、配置形を作る（照合のときに作ったものがあれば、それを使う）。
2. **監査**: `audit.md` に従う。対象は、配置形のうち、手元に無いファイルと、手元と要約値が違うファイルである。
3. **承認**: 手順5の承認に含める。一覧には、参照物の名前、取得元とコミット、置き場、ファイル数を書く。手元で変えられていたファイルを上書きする場合は、その変更が消えることを書く。
4. **配置**: 監査した配置形を、そのまま `external/<名前>/` へ上書きで置く。取り直さない。配置形に無いファイルが手元に残っていれば、手順5の「手元にだけあるファイル」として扱う（消さない）。
5. **記録**: `.skill-sync/external/<名前>.sha256` と、`records.json` の `externals` の項目を書く。
6. **検証**: 手元の `external/<名前>/` が記録の一覧どおりであることを確かめる。

## 書き込めない場所にある複製

宣言ファイルを持つ行が、書き込めない場所（プラグイン機構の管理下、配布キャッシュ、他のエージェントの置き場、プロジェクトスコープ）にあるときは、参照物を取得しない。上流にも問い合わせない。

- その複製に、宣言の参照物がすべてそろっている（`external/<名前>/` がある）→ 備考に「参照物あり（更新は持ち主のエージェントで）」と書く。
- そろっていない → 備考に「参照物なし（この場所には取得できない）」と書く。
- 参照物のそろった複製が、実行中のエージェントから見えるどの置き場（自分の置き場と、互換読み込みで見える置き場）にも無ければ、**自分の置き場への導入を候補に出す**。導入すると同じスキルが2か所に存在することになる、と伝える。
