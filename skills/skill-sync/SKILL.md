# skill-sync: 導入済みスキルの一覧と更新

> **skill version**: 1.1.0

セッション内で初めて本スキルを使用するときは「skill-sync スキル v1.1.0 を使用します」と宣言する。

同じスキルを複数のコーディングエージェントへ配っていると、どこにどの版が入っているかが分からなくなり、
一部だけ古いまま放置される。本スキルは**導入済みスキルの版を一覧し、配布元の最新版と突き合わせ、
ユーザーが選んだ対象だけを更新する**ための手順書である。

**このスキルは利用者のホームディレクトリ配下に書き込む。**したがって
**更新の適用はユーザーの承認を得てから行う**。承認なしにファイルを置き換えてはならない。

## 書き込みの範囲（最優先の制約）

**本スキルが書き込むのは、本スキルを実行しているエージェント自身のコンフィグディレクトリ配下に限る。**
それ以外の場所への書き込みは、**ユーザーが明示的にその場所を指示した場合を除き、行ってはならない。**

他のエージェントのスキルが古いと分かっても、**こちらから書き換えない**。
別のエージェントの設定を勝手に触ることは、利用者が本スキルに委ねた範囲を超える。
更新が必要なら、**そのエージェント上で本スキルを実行してもらう**。

自分がどのエージェントとして動いているかが判別できない場合は、**書き込まない**。
判別できない旨を伝え、以降の適用はユーザーの指示を待つ。

## 前提と一般化ルール

- **エージェントの種類をハードコードしない。** 後述の「既知のエージェント」表は*データ*であり、
  手順そのものは表に無いエージェントにも通用する形で書いてある。表に載っていないエージェントを
  使っている場合は、汎用探索（手順2）で拾う。
- スキルの版は `SKILL.md` の frontmatter の `metadata.version` に入っている。
  **これが無いスキルは「版不明」として扱い、エラーにしない**。古い配布物には版が入っていない。
- 配布元は `index.json` という1ファイルで表現される。既定は下記だが、
  **利用者が別の配布元を使っている場合はその URL に読み替える**。

  ```
  https://raw.githubusercontent.com/xhighhongo41/agent-skills/main/skills/index.json
  ```

- **判定と適用を混ぜない。** まず全体を一覧して見せ、対象を選ばせ、承認を取ってから書き込む。

## 手順

### 1. 配布元の最新版を取得する

`index.json` を取得し、`skills[]` の各要素から `name` / `version` / `files` を読む。
`files` はスキルフォルダ内の全ファイルの相対パスであり、**更新時に取得すべきファイルの一覧そのもの**である。

各ファイルの取得先は `{index.json を置いている URL のディレクトリ}/{name}/{files の各パス}` で決まる。

取得に失敗した場合（オフライン、URL 誤り、配布元の障害）は**そこで止めない**。
「配布元に接続できなかった」と明示したうえで、手順2〜3のローカル一覧までを実行して報告する。
その状態では更新の要否は判定できないので、**更新の適用には進まない**。

### 2. 導入済みスキルを走査する

**まず、本スキルを実行しているエージェント自身のコンフィグディレクトリを走査する。**
これは更新の対象になりうる唯一の場所であり、ここを見ないと本スキルは目的を果たせない。

あるエージェントのスキルの置き場所は、次の順で決める。

1. **環境変数による上書きを最優先する。** 表の「上書き」欄の変数が設定されていればそちらを使う。
2. 「既知のエージェント」表のパスを引く。
3. **表に無いエージェント、または表のパスが存在しない場合は汎用則で探す。**
   ほとんどのエージェントはスキルを `<そのエージェントの設定ディレクトリ>/skills/<スキル名>/SKILL.md`
   に置く（`skills` が単数形 `skill` の実装もある）。設定ディレクトリの場所は
   そのエージェントの文書か、ホーム直下のドットディレクトリから判断する。

見つけた各ディレクトリの直下を1階層だけ列挙し、`<スキル名>/SKILL.md` があるものをスキルとみなす。
`SKILL.md` から frontmatter の `name` と `metadata.version` を読む。

走査で守ること:

- **エージェント本体が管理する領域は走査から除外する**（「書き込んではいけない場所」を参照）。
  利用者のスキルではないため、一覧に出す意味がない。
- **同じ実体を二重に数えない。** 複数のエージェントが同じディレクトリを読む構成があるため
  （表の「互換読み込み」欄を参照）、実パスで名寄せする。
- プロジェクトスコープのスキル（作業中のリポジトリ配下）は、**ユーザースコープとは別行**として扱う。
  リポジトリの持ち物なので、勝手に更新しない。

### 3. 比較して一覧を提示する

エージェント × スキルの表にして、状態を次の6種で示す。

| 状態 | 意味 | 既定の扱い |
|---|---|---|
| 最新 | ローカルと配布元の版が一致 | 何もしない |
| 更新あり | 配布元の版が違う | **更新候補** |
| 未導入 | 配布元にあるがローカルに無い | **導入候補**（ユーザーが望む場合のみ） |
| 版不明 | ローカルに `metadata.version` が無い | **更新候補**（古い配布物の可能性が高い） |
| ローカルが新しい | ローカルの版が配布元より進んでいる | **更新しない。** 手元で改造した可能性があるので必ず知らせる |
| 配布元に無い | ローカル固有のスキル | 触らない |

配布元の版は**文字列として比較する**。大小関係の判定に頼らず、「一致しない＝更新候補」とする。
「ローカルが新しい」の判定だけは版番号を数値として読み、判断がつかなければ「版が食い違う」と報告する。

### 4. 更新対象を選ぶ

**黙って全件更新してはならない。** 一覧を見せたうえで、何を更新するかを決めてもらう。

**更新の候補にできるのは、自エージェントのコンフィグディレクトリ配下にあるものだけ**である
（「書き込みの範囲」を参照）。それ以外は一覧に出ていても候補から外し、
**そのエージェント上で本スキルを実行するよう案内する**。

呼び出し時の引数でスキル名やエージェント名が指定されていればそれを対象とする。
指定が無ければ候補を提示して選択を促す。選択の粒度は次の3つを受け付ける。

- **スキル単位**（例: あるスキルだけを全エージェントで更新する）
- **エージェント単位**（例: あるエージェントだけを最新に揃える）
- **その組み合わせ**、および「更新候補すべて」

「ローカルが新しい」ものは既定で対象から外す。**上書きするとユーザーの改造が消える**ため、
含めるかどうかを個別に確認する。

### 5. 更新を適用する

**書き込む前に、書き込み先が自エージェントのコンフィグディレクトリ配下であることを確認する。**
範囲外のものが混じっていたら、**ユーザーがその場所を明示的に指示していない限り書き込まない**。
指示が無ければ、その1件を適用せずに「どこへ書けなかったか」を報告する。

**承認は、書き込みを始める直前に1度だけ求める。** 何をどこへ書くかを一覧で示してから尋ねる。
承認が得られたら、選ばれた対象の範囲内では**1件ずつ聞き直さずに最後まで実行してよい**。

対象1件ごとに次を行う。

1. 配布元から、そのスキルの `files` に挙がっている**全ファイル**を取得する。
   `SKILL.md` だけでなく、付属のメタデータファイルや参照文書も含めて取得する。
2. 取得がすべて成功してから配置する。**部分的に取得できた状態で書き始めない**
   （途中で失敗すると、中途半端に混ざったスキルフォルダが残る）。
3. 配置先のスキルフォルダへ上書きする。
4. **配布元に無いファイルがフォルダに残っている場合は、消さずに報告する。**
   利用者が意図して置いたファイルかもしれない。削除は別途確認を取る。
5. 配置後に `SKILL.md` を読み直し、`metadata.version` が配布元の版と一致することを確認する。

**途中で失敗したら、そこで残りを止める。**「どこまで適用したか」「どれが未適用か」を必ず報告する。
部分的に適用された状態を隠してはならない。

### 6. 結果を報告する

適用したもの・スキップしたもの・失敗したものを分けて示す。
失敗があれば原因と、次に取るべき手段（再実行、手動コピー、配布元の確認）を添える。

## 既知のエージェントのスキルディレクトリ

**この表はデータである。**内容は古くなりうるので、表のパスが存在しなければ手順2の汎用則へ落とす。

| エージェント | ユーザースコープ | 上書き | 根拠 |
|---|---|---|---|
| Claude Code | `~/.claude/skills/` | `CLAUDE_CONFIG_DIR` | 実機で確認 |
| OpenAI Codex | `~/.codex/skills/` | `CODEX_HOME` | 実機で確認。公式文書はベンダ中立の `~/.agents/skills/` も挙げるが、実機には未生成だった |
| OpenCode | `~/.config/opencode/skills/` | `XDG_CONFIG_HOME` / `OPENCODE_CONFIG_DIR` | 実機で確認。単数形の `skill/` も受理される |

Windows では `~` をユーザープロファイル（`%USERPROFILE%`）に読み替える。
OpenCode は Windows でも `~/.config/opencode/` を使う点に注意する（確度は中程度なので、
無ければ汎用則で探す）。

**互換読み込み**: OpenCode は自分のディレクトリに加えて `~/.claude/skills/` と `~/.agents/skills/`
も読む。したがって Claude Code 側へ入れたスキルは OpenCode からも見えており、
**両方へコピーすると二重に見える**。一覧では実パスで名寄せし、
「1か所にあり2つのエージェントから見えている」ことが分かるように示す。

**プロジェクトスコープ**: `.claude/skills/` / `.opencode/skill(s)/` / `.agents/skills/` を
作業中のリポジトリ配下に持つ構成がある。一覧には出すが、更新の既定対象にはしない。

## 書き込んではいけない場所

- **自エージェントのコンフィグディレクトリの外側すべて**（「書き込みの範囲」）。
  ユーザーがその場所を明示的に指示した場合のみ例外とする。
- **他のエージェントが所有するスキルディレクトリ。**
  互換読み込みによって自分から見えていても、**実体の持ち主が自分でなければ書かない**。
  例えば OpenCode は `~/.claude/skills/` を読むが、そこは Claude Code の持ち物である。
- **エージェント本体が管理する領域。** 例えば Codex は自身のシステムスキルを
  `~/.codex/skills/.system/` に置き、目印のマーカーファイルを持つ。
  **走査対象からも外す**（利用者のスキルではないため一覧に出す意味がない）。
- **プラグイン機構の管理下。** Claude Code のプラグイン経由で入ったスキルは
  `~/.claude/plugins/` 配下のキャッシュにあり、ユーザースコープのスキルディレクトリには現れない。
  ここを直接書き換えても次の更新で消える。**一覧には「プラグイン経由」として出し、
  更新はプラグイン機構のコマンド（`/plugin marketplace update <マーケットプレイス名>` など）を案内する。**
- 迷ったら書かない。**書き込み先が利用者の意図した場所かどうか確信が持てない場合は、
  適用せずに手順だけを提示してユーザーに委ねる。**

## うまくいかないときの確認

- **スキルが一覧に出ない**: そのエージェントが単数形 `skill/` を使っていないか、
  設定ディレクトリが環境変数で移動されていないかを確認する。
- **更新したのにエージェントが古い版を使う**: 多くのエージェントは起動時にスキルを読む。
  再起動を案内する。キャッシュを持つ機構ではキャッシュの更新も必要になる。
- **版が一致しているのに中身が違う**: 配布元で版を上げずに本文だけ直した場合に起きる。
  本スキルは版でしか判定しないため、疑わしければ**その1件を明示的に再取得する**よう案内する。
