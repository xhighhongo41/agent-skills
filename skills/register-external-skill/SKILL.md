# register-external-skill: 他者のリポジトリのスキルを取り込む

> **skill version**: 1.0.0

セッション内で初めて本スキルを使用するときは「register-external-skill スキル v1.0.0 を使用します」と宣言する。

他者が公開しているスキルを、自分のエージェントに「お気に入り」として取り込み、以後は `skill-sync` で更新を確認できるようにするための手順書である。
本スキルが行うのは**取得・列挙・対象判定・選択・frontmatter の補い・配置・由来の記録**までで、更新の確認と適用は `skill-sync`、削除は `remove-skill` が担う。

**このスキルは利用者のホームディレクトリ配下に書き込む。** 配置はユーザーの承認を得てから行う。承認なしにファイルを置いてはならない。

## 書き込みの範囲（最優先の制約）

**本スキルが書き込むのは、本スキルを実行しているエージェント自身のコンフィグディレクトリ配下に限る。**
それ以外の場所への書き込みは、**ユーザーが明示的にその場所を指示した場合を除き、行ってはならない。**
他のエージェントへ同じスキルを入れたいときは、**そのエージェント上で本スキルを実行してもらう**。
自分がどのエージェントとして動いているかが判別できない場合は、**書き込まない**。判別できない旨を伝え、以降はユーザーの指示を待つ。

## 前提と一般化ルール

- **引数**はリポジトリの指定である。`https://` で始まる URL、`owner/repo`（`https://github.com/owner/repo` に展開する）、またはローカルのパスを受け付ける。
  末尾に `#<ref>`（ブランチまたはタグ）を付けられる。**引数が無ければ**、手元の外部由来スキル（下記の由来キーを持つもの）の導入元を集めて一覧し、どれかを選ぶか URL を求める。
- スキルの単位は `SKILL.md` を持つディレクトリである（Agent Skills 標準）。スキル名はディレクトリ名と一致させる。
- **外部のスキルの frontmatter は、こちらの規約に従っていない前提で読む。** 無いこともあり、独自のキーを持つこともある。
  標準の `compatibility` は環境要件の自由文であり、対象エージェントを決まった語で宣言しているとは限らない（手順3）。
- **本文は変えない。** 変えてよいのは frontmatter だけで、それも「無いものを足す」「名前をディレクトリ名に合わせる」「由来を記録する」に限る。
  本文を書き換えたくなったら、それは取り込みではなく改造であり、本スキルの範囲外である。
- **由来の記録**は `SKILL.md` の frontmatter の `metadata` に、次の平たい文字列キーで書く（Agent Skills 標準は `metadata` を文字列から文字列への対応表と定めている。入れ子にしない）。
  `skill-sync` はこれを読んで更新を判定する。

| キー | 値 |
|---|---|
| `origin` | 取得に使った URL またはローカルパス（認証情報を含めない） |
| `origin-path` | リポジトリ内のスキルディレクトリの相対パス（ルート直下なら `.`） |
| `origin-ref` | 取得したブランチまたはタグ（指定が無ければクローン時の既定ブランチ名） |
| `origin-commit` | 取得時の HEAD のコミット識別子 |
| `origin-digest` | 上流 `SKILL.md` の**本文**の要約値。`sha256:` に続けて64桁 |
| `origin-fetched` | 取得日（`YYYY-MM-DD`） |

- **要約値の計算**: 本文は閉じ `---` の次の行以降（frontmatter が無ければ全文）。改行を LF に揃え、末尾の改行を1つにした UTF-8 のバイト列の SHA-256（`shasum -a 256` または `hashlib`。16進は小文字）。
  frontmatter を含めないのは、手元の frontmatter が本スキルで補われることがあるためである。`skill-sync` も同じ規則で計算する（**直すときは両方を同時に直す**）。
- 自エージェントの判別とスキルの置き場は、末尾の「既知のエージェントのスキルディレクトリ」の表で引く。表は `skill-sync` と同じであり、**直すときは両方を同時に直す**。

## 手順

### 1. 取得する

一時ディレクトリ（作業中のリポジトリの外。終了時に削除する）へ浅く取得する。

```
git clone --depth 1 [--branch <ref>] <URL またはローカルパス> <一時ディレクトリ>
```

GitHub でもそれ以外のホスティングサービスでも、ローカルのパスでも同じコマンドで扱う。取得後に `git rev-parse HEAD` で識別子を控え、`--branch` を付けなかったときは取得されたブランチ名を控える。
取得に失敗したら**中止して理由を報告する**（認証が原因なら、GitHub では `gh auth status` の確認を案内する）。別の取得手段へ勝手に切り替えない。

### 2. 走査して列挙する

一時ディレクトリの中で、`.git` を除き**深さ4まで**の `SKILL.md` を探す。置き方はリポジトリによって違う（`skills/<name>/`、`.claude/skills/<name>/`、`.agents/skills/<name>/`、ルート直下など）ので、特定の階層を決め打ちしない。
各候補について次を読む: ディレクトリ名、frontmatter の有無と `name` / `description` / `compatibility` / `metadata.version`、本文の行数、同梱ファイルの数、**手元の状態**（未導入／導入済み〈版・由来〉／同名のスキルが別の由来で存在）。

同名の候補が複数あれば、パス付きで全部列挙する（選べるのは1つだけ。名前はディレクトリ名で決まる）。

### 3. 対象を判定する

自分がどのエージェントとして動いているかを表で引き、候補ごとに次の順で判定する。

1. `compatibility` が表の「`compatibility` の値」の語（`claude-code` / `codex` / `opencode` をカンマ区切りで並べたもの）に一致する → 自エージェントを含まなければ**「対象外」**。
   既定で候補から外すが、利用者が明示的に含めたいと言えば、動かない見込みであることを伝えたうえで従う。
2. それ以外の `compatibility`（自由文）→ そのまま表示し、判断を利用者に委ねる。対象外と決めつけない。
3. `compatibility` が無い → 全エージェント向けとして扱う。
4. パスが `.claude/` 配下にあるものは「Claude Code 向けの配置」と注記する。対象外にはしない（多くのスキルは他のエージェントでも動く）。

自分がどのエージェントか判別できない場合は判定せず、その旨を示して利用者に委ねる。**他エージェントへは導入しない**（「書き込みの範囲」）。

### 4. 選ぶ

表（番号／名前／説明の先頭／パス／対象／手元の状態）を示し、導入するものを選んでもらう（複数可）。引数でスキル名が指定されていればそれを対象にする。
**黙って全件入れてはならない。**

### 5. frontmatter を検査し、必要なら補う

選ばれた1件ごとに、上流の `SKILL.md` の frontmatter を検査する。補う前後の差分を示し、**了解を得てから**次の処理を行う。

- (a) **frontmatter が無い** → `name`（ディレクトリ名）、`description`（本文冒頭の見出しと段落から案を作る）、`metadata`（由来キー）を持つ frontmatter を先頭に足す。
  `description` の案に了解が得られなければ、**その1件は導入しない**（本文を変えてまで入れない）。
- (b) **`name` がディレクトリ名と違う** → ディレクトリ名に合わせる（標準で一致が必須）。
- (c) **標準外のキーがある** → **そのまま残す**。壊さない。
- (d) **`metadata` が無い** → 作る。あれば由来キーを足す。上流の `metadata.version` は**そのまま**にし、無くても作らない（`skill-sync` は版の無い外部由来スキルを要約値で判定する）。

**閉じ `---` 以降（本文）は1文字も変えない。** 要約値は手順1で取得した上流の `SKILL.md` から計算する。

### 6. 配置する

配置先は `<自エージェントの置き場>/<name>/`。書き込む前に、配置先が自エージェントのコンフィグディレクトリ配下であることを確認する。**承認は配置を始める直前に1度だけ求める**（何をどこへ置くかを一覧で示す）。

- スキルディレクトリ全体をコピーする（`.git` と `__pycache__` は除く）。
- **同名のスキルが既にある場合**: 由来（`origin` と `origin-path`）が一致するなら「更新は `skill-sync` で行う」と案内して飛ばす。
  一致しない（こちらの収録スキル、ローカル固有、別の導入元）なら**上書きしない**。別名での導入はしない（名前はディレクトリ名と一致が必須）。利用者が手元のものを消すか、諦めるかを選ぶ。
- 配置後に手順5で補った frontmatter と由来キーが書かれていることを読み直して確かめる。

### 7. 由来を記録する

手順5で frontmatter に書いた由来キー（6つ）が、手順1で控えた値（URL・パス・ref・コミット・要約値・日付）と一致することを確かめる。
`origin` に認証情報（トークンや利用者名）を含めない。

### 8. 設定に足す

自エージェントの必要・不要の設定ファイル（`skill-sync` の「必要・不要の設定ファイルの在処」の表。無ければ設定ディレクトリ直下の `skill-sync.json`）が**既にあれば**、導入したスキルを `true` にする（他の項目と未知のキーは変えない）。
設定ファイルが無ければ作らない（初期化は `skill-sync` の役目）。

### 9. 報告する

導入したスキル（名前・配置先・由来）、補った frontmatter の内容、飛ばしたもの（理由付き）、失敗したものを分けて示す。
「次回以降の更新確認は `skill-sync`、削除は `remove-skill`」と添える。
取り込み元のリポジトリに公式の導入手段がある場合（Claude Code のプラグインマーケットプレイス、Codex の `skill-installer` など）は、その存在を1行で案内する。導入は常に自分の置き場へ行い、公式手段に任せない。

## 既知のエージェントのスキルディレクトリ

**この表はデータである。** `skill-sync` の同名の表と同じ内容であり、直すときは両方を同時に直す。表のパスが存在しなければ、
汎用則（`<そのエージェントの設定ディレクトリ>/skills/<スキル名>/SKILL.md`。単数形 `skill` もある）で探す。

| エージェント | ユーザースコープ | `compatibility` の値 | 環境変数による上書き |
|---|---|---|---|
| Claude Code | `~/.claude/skills/` | `claude-code` | `CLAUDE_CONFIG_DIR` |
| OpenAI Codex | `~/.codex/skills/` | `codex` | `CODEX_HOME` |
| OpenCode | `~/.config/opencode/skills/` | `opencode` | `XDG_CONFIG_HOME` / `OPENCODE_CONFIG_DIR` |

Windows では `~` をユーザープロファイル（`%USERPROFILE%`）に読み替える。

## 書き込んではいけない場所

- **自エージェントのコンフィグディレクトリの外側すべて**（「書き込みの範囲」）。
- **他のエージェントが所有するスキルディレクトリ。** 互換読み込みで自分から見えていても、持ち主が自分でなければ書かない。
- **プラグイン機構や配布経路のキャッシュの管理下。** 書いても次の更新で消える。
- **作業中のリポジトリ配下（プロジェクトスコープ）。** 利用者が明示的に指示した場合だけ置く。
- 迷ったら書かない。手順だけを提示してユーザーに委ねる。

## うまくいかないときの確認

- **取得できない**: URL の綴り、認証、ネットワークを確認する。プライベートリポジトリは認証済みの `git` でないと取れない。ローカルパスでは `--depth` が無視される旨の警告が出るが、取得は成功しているので問題ない。
- **`SKILL.md` が見つからない**: 深さ4より深い階層にあるか、別名のファイルを使っている。パスを指定してもらい、それでも無ければそのリポジトリはスキルを配っていない。
- **同名が複数ある**: パスで選んでもらう。入れられるのは1つだけ。
- **`compatibility` の意味が分からない**: 自由文なので本スキルは判定しない。表示して利用者に委ねる。
- **導入したのにエージェントが認識しない**: 多くのエージェントは起動時にスキルを読む。再起動を案内する。`name` がディレクトリ名と一致しているかも確かめる。
- **`skill-sync` が「配布元に無い」と出す**: 由来キーが書かれていない。手順5〜7をやり直す。
