# 構成物の数え方と配置の記録

> このファイルは skill-sync と register-external-skill が同じ文で持つ。直すときは両方を同時に直す。

スキルのフォルダにあるファイルのうち、何を比較・取得・報告の対象に数えるかと、配置したときに残す記録の形式を定める。
呼び出し元の手順が「構成物」「配置の記録」と書いているときは、ここの定義に従う。

## 構成物

構成物とはスキルのフォルダにあるファイルのうち、下の表に当たるものを除いた全部である。
比較するとき、取得するとき、手元にだけあるファイルを報告するときのいずれでも、表に当たるものは数えない。

| 種類 | 当たるもの |
|---|---|
| キャッシュ・一時ファイルのディレクトリ | `.git`、`__pycache__`、`.pytest_cache`、`.ruff_cache`、`.mypy_cache`、`node_modules`、`.venv` |
| キャッシュ・一時ファイル | `*.pyc`、`*.pyo`、`.DS_Store`、`Thumbs.db`、`*.swp`、`*~`、`*.tmp` |
| 配置の記録 | スキルのフォルダ直下の `.skill-sync/` |
| 参照物の置き場 | スキルのフォルダ直下の `external/`（宣言ファイル `external.json` を持つスキルに限る） |
| 配布の機構が置く記録 | 配布キャッシュにスキルごとに置かれる、取得時の版の記録（`.opencode-version` など） |

- 表のディレクトリはどの階層にあっても、その下ごと除く。
- 参照物の置き場の中身は参照物として別に数える（skill-sync が扱う）。宣言ファイルがあれば、その形式が違っていても、`external/` は参照物の置き場として扱う。宣言ファイルを持たないスキルの `external/` は、ふつうのディレクトリとして数える。
- シンボリックリンクは構成物に数えず、取得もしない。見つけたらパスを報告する（リンクの先がスキルのフォルダの外を指しうるため）。
- 収録スキル（配布元の一覧に載るスキル）では、配布元の一覧の `files` が配布される構成物の一覧である（配布元は隠しファイルと `__pycache__` を除いて一覧を作るので、上の表と矛盾しない）。手元のフォルダにあって `files` に無い構成物が、「手元にだけあるファイル」である。

## 配置の記録

配置の記録は上流から取得して配置したファイルの一覧と要約値、取得元とコミットを残したものである。
次回の照合で、手元が変わったのか上流が変わったのかを区別するために使う。置き場はスキルのフォルダ直下の `.skill-sync/` である。

- 配布されない。構成物に数えない。スキルを削除すると、フォルダごと消える。
- 作るのは、外部由来スキルの付属ファイルと、参照物である。収録スキル自身のファイルには作らない（配布元の一覧と直接比べられる）。

| ファイル | 対象 | パスの基準 |
|---|---|---|
| `.skill-sync/origin.sha256` | 外部由来スキルの付属ファイル（上流から配置した構成物のうち `SKILL.md` を除いたもの） | スキルのフォルダ |
| `.skill-sync/external/<参照物の名前>.sha256` | 参照物として配置した全ファイル | `external/<参照物の名前>/` |
| `.skill-sync/records.json` | 取得元・コミット・取得日 | — |

外部由来スキルの `SKILL.md` は frontmatter の `origin-digest`（本文だけの要約値）で扱う。
取り込みのときに frontmatter を補うので、ファイル全体の要約値では比べられない。

### 一覧と要約値の形式

`*.sha256` は標準のチェックサム形式のテキストである。

- 1行が1ファイルで、「SHA-256 の16進64桁（小文字）、空白2つ、相対パス」の形にする。
- 相対パスの区切りは `/` とし、先頭に `./` を付けない。パスの順に並べる。改行は LF とする。
- 要約値はファイルのバイト列そのものから取る（改行を揃えるなどの正規化をしない）。
- 対象のファイルが1つも無ければ、空のファイルにする（記録が有ることと、対象が無いことを区別するため）。

作り方の例を示す（基準のディレクトリで実行する）。一覧に入れるのは、上の表の「対象」だけである。この例は一時ディレクトリに取得した上流の構成物や、配置形のように、対象だけが入ったディレクトリで使う。
スキルのフォルダそのものを基準にするときは、`SKILL.md`、`.skill-sync/`、`external/`、キャッシュ・一時ファイルを除く条件を足す。
`shasum` が無ければ `sha256sum` を使う。PowerShell の `Get-FileHash` や Python の `hashlib` など、同じ結果になる手段ならどれでもよい。

```
find . -type f ! -name '.DS_Store' | sed 's|^\./||' | LC_ALL=C sort | tr '\n' '\0' | xargs -0 shasum -a 256
```

手元が記録どおりかは、基準のディレクトリで `shasum -a 256 -c <記録のファイル>` を実行すれば確かめられる（内容が違うファイルと、無くなったファイルが挙がる）。
記録に無いファイルが手元に増えていないかは、手元の一覧と記録のパスを比べて確かめる。

取得したファイルは、取得したバイト列のまま置く（コピーのコマンドを使う。エージェントの編集ツールで書き写すと、末尾の改行などが変わって要約値が合わなくなる）。

### 取得の記録の形式

`records.json` は厳格な JSON（コメント・末尾カンマ無し）で、`format` は常に `1` である。

```json
{
  "format": 1,
  "origin": { "commit": "<上流のコミット>" },
  "externals": {
    "<参照物の名前>": {
      "origin": "<取得に使った URL>",
      "path": "<リポジトリ内のパス>",
      "ref": null,
      "include": null,
      "commit": "<取得時のコミット>",
      "fetched": "<取得日 YYYY-MM-DD>"
    }
  }
}
```

- `origin.commit` は外部由来スキルの付属ファイルの一覧（`origin.sha256`）を作ったときの上流のコミットである。外部由来スキルでなければ `origin` は書かない。
- `externals` は参照物の名前ごとに、取得に使った宣言の写し（`origin`・`path`・`ref`・`include`。宣言に無い項目は `null`）と、取得時のコミット、取得日を持つ。参照物が無ければ `externals` は書かない。
- 未知のキーがあっても異常ではない。書き戻すときは保持する。

### 記録の扱い

- 書く時機: 記録はその対象の配置が終わってから書く。配置の途中で止まった対象は、次回の照合で「記録なし」か「記録が古い」になり、利用者の改変としては数えられない。
- 記録が古い: `origin.commit` が `SKILL.md` の frontmatter の `origin-commit` と違う記録は古い（記録を作らない版のツールや手作業で更新された場合に起こる）。`origin.sha256` はあるのに、`records.json` かその `origin.commit` が無い場合も、古い記録として扱う。記録が無い場合と同じに扱い、備考で知らせる。
- 記録が読めない: JSON として壊れている、`format` が `1` でない、チェックサムの行の形が違う、のいずれかに当たる記録は、無い場合と同じに扱い、読めなかった旨を知らせる。
- 記録に無い手元のファイル: 利用者が足したファイルや、上流から消えた後も手元に残したファイルが当たる。照合では数えず、「手元にだけあるファイル」として報告する。消さない。記録は取得した上流の一覧から作るので、手元に残したファイルは記録に入らない。
- 宣言から外れた参照物の記録: 宣言に無い名前の参照物のディレクトリを、利用者の答えに従って削除したときは、その名前の記録（`.skill-sync/external/<名前>.sha256` と、`records.json` の項目）も消す。残すと答えられた間は、記録もそのままにする。
